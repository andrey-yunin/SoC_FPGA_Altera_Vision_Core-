## Текущий последовательный разбор тракта

Пользователь уточнил ожидаемый формат: двигаться от реальных сигналов и данных к обоснованию каждого узла. Актуальная граница по указанию пользователя: FPGA автономно выполняет захват, буферизацию, DMA и смену буферов; HPS занимается собственными задачами и получает завершённые данные через отдельный интерфейс. Прежний основной вариант с DDR3 HPS и ARM-дескрипторами снят. Теперь предлагается внешняя SDRAM 64 МБ на стороне FPGA, её контроллер и аппаратный автомат выдачи заданий mSGDMA либо собственный writer. DDR3 HPS остаётся для задач ARM. Конкретные DMA/контроллер, число буферов и интерфейс чтения результатов не утверждены. Следующий шаг — определить адресные области, права владения и обмен завершёнными данными без зависимости захвата от обслуживания ARM.

Согласовано 2026-11-05: буфер RAW12 для ARM — uint16_t, отсчёт в [11:0], старшие [15:12] нулевые; little-endian как контракт памяти. Пиксель 0xABC хранится байтами BC 0A, соседние пиксели занимают по 2 байта. Без отступов stride = width × 2; пример 1280×800 даёт stride 2560 байт и кадр 2 048 000 байт. Порядок байтов реальной ARM/Linux-системы и соответствие DMA этому контракту ещё проверить. Формат хранения согласован; камера, ширина передачи DMA, память, кэш и схема владения буферами этим указанием не утверждены.

Конкретизация архитектуры пользователя: автономная FPGA и граница с HPS по памяти/готовым данным — исходное предложение пользователя, а не отдельная архитектура ассистента. Дополнения ассистента: потоковые локальные операции до кадровой памяти; отдельная запись mSGDMA под аппаратным управлением в SDRAM FPGA; три кадровых слота и отдельная очередь готовых результатов для HPS. Передача изображений — отдельный арбитрируемый канал. Это ещё не согласованный выбор. При примере 1280×800×16 бит×60 FPS запись требует 122,88 МБ/с, запись плюс одно полное чтение — 245,76 МБ/с без накладных расходов; достижимость на SDRAM не подтверждена. ## Переоценка устаревшего SDRAM IP — 2026-11-05
